# MicroBench 显微颗粒观察工作台

本地显微图像颗粒量测与复核工具。访问 http://127.0.0.1:18920 ，点击“载入合成演示”，选择视野并“应用设置并分析”，在叠加图和量测表核对对象。演示由程序绘制，并非真实显微照片；结果是图像量测近似，不用于医疗诊断。

正常功能包括多视野PNG/JPEG/单页TIFF/WebP导入及EXIF方向处理、单/多条标尺最小二乘物理标定、源图多边形ROI、三种阈值及形态学对象提取、标签图与对象叠加、物理面积/周长/等效直径/椭圆轴量测、对象强度积分与圆度、人工排除对象并保留历史结果、带标定距离的强度线剖面、源图距离/角度/面积标注、图像曝光与清晰度读数、批次视野数密度/粒径比较、命名快照恢复、不可变分析历史、PNG/标签图/CSV/清单结果交付、完整可编辑工程ZIP往返，以及跨帧对象追踪会话：按观测秒把多视野分析结果组成时间序列，自动关联生成轨迹、漏检接续与合并/分裂候选，在原图叠加中确认、驳回或手动改接，按真实时间与标定导出逐时位置、逐边速度、可靠连续段与事件关系。

图像像素中心坐标为整数x/y，原点左上，x右y下。物理标定为各向同性，每像素长度。标尺参考用已知长度对像素距离的零截距最小二乘拟合。显示图缩放不改变源坐标。强度是RGBA先以黑底合成后按固定RGB亮度权重计算的0–1显示色值；不是光子计数或已做仪器辐射标定的数据。透明像素不进入ROI，边界对象可排除。面积为标签像素数，周长为像素中心轮廓长度，椭圆轴来自像素点协方差。填孔不跨ROI无效区。对象ID仅在对应分析结果内有意义，每次分析重新编号；历史量测固定保存当时源图、标定、ROI与设置。修改这些输入会失效当前结果，旧结果仍可查看下载。排除选择创建新结果，旧结果不变。新分析发布时核验工程revision，期间修改则拒绝旧发布。

追踪会话固定引用一组不可变分析结果（run）及其中对象编号，节点id为帧序号加run内对象号；重新分析某视野只会产生新run，旧会话不迁移、不套用新编号，并在帧上标记“已过期”，仍可核对与导出。自动关联按空间门限（直径倍数）与面积比贪心配对：唯一近邻直接确认，分数接近的竞争配对、合并/分裂的一对多配对全部保留为待核对候选，程序不擅自续号；允许0–3帧漏检，跨漏检帧的接续边标注GAP且不进入可靠速度。单条确认或手动加边若与既有确认边共享端点，会把冲突边降级为候选；明确的合并/分裂请用“整组确认”，同一节点可同时保留多条确认边。轨迹、谱系、事件与速度全部由已确认边即时派生，人工改接后整体重算，轨迹名按稳定头节点持久化、旧号不复用。合并团/分裂团本身成为独立轨迹并标记is_event_blob，其位移不计入任何单体速度；可靠速度段只包含相邻帧、无事件、已确认的逐边。追踪ZIP含positions/links_velocities/reliable_segments/events/tracks五个CSV、会话JSON与各帧叠加PNG，判断随工程ZIP完整往返（格式版本2）。

启动 `docker compose -p solo20-microbench up -d --build`，持久数据为独立命名卷 `solo20-microbench-data`；删除容器保留卷，`down -v`删除数据。也可按requirements安装依赖后执行 `./start.sh`；Python3.11/3.12按条件锁定依赖。`MICROBENCH_DATA_DIR`与`PORT`指定数据和端口。

预算：单图20MB、1200万像素、边长4096，每工程32图、100份分析、30快照、20个追踪会话，每幅分析2000对象，单会话最多32帧、8000节点、每节点6条候选，ROI/标注最多100顶点。工程ZIP96MB压缩、192MB展开、500成员。所有计算CPU同步；实际验证512×360合成视野，不承诺极限规模实时性能。阈值法适用于背景与对象可分辨的二维图像，不含深度学习识别、语义分类、粘连团自动拆分为单体（合并/分裂仅生成候选并要求人工整组确认）、三维体积重建、仪器畸变补偿或真实光谱解混。

`/prepare`为完整自有图像准备工具，其`image_lab`及`prepare.html`、`app.js`、`style.css`按字节复用自本工作区solo_19正常版本，供量测前配准、色彩/曝光、图像合成和区域处理。准备结果下载后导入MicroBench；未混入旧项目动态影像编排业务。MicroBench新业务在`microbench/`和`bench.*`中，负责视野、标定、对象、量测、历史、工程及交付。后台统计仅包含实际Python后台，排除前端、文档、脚本、依赖和生成数据。
